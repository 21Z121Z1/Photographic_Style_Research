# 实况照片 HDR 重建

双击 [HDR重建.command](/Users/retriedstormtrooper/Downloads/LivePhotoHDR/HDR重建.command)，将一个或多个实况照片文件夹拖入终端窗口，按回车开始。每个文件夹中需要恰好一个 HEIC 和一个 MOV，两者的实况配对 UUID 必须一致。

也可以在终端直接输入路径。

```bash
/Users/retriedstormtrooper/Downloads/LivePhotoHDR/HDR重建.command \
  "/路径/IMG_1234" \
  "/路径/IMG_1235"
```

默认执行完整重建和验证，然后把 `/路径/IMG_1234` 替换为 `/路径/IMG_1234.pvt`。原文件夹完整保存在同级隐藏目录 `.LivePhotoHDR-originals/` 中，每次使用唯一的备份名称。脚本不会删除备份，也不会覆盖已经存在的 PVT。转换失败时保留输入文件夹原路径。中间数据和失败日志保存在同级 `.LivePhotoHDR-work/` 中。

需要保留原文件夹原路径时，增加 `--keep-originals`。只检查配对和依赖时，增加 `--check`。

```bash
/Users/retriedstormtrooper/Downloads/LivePhotoHDR/HDR重建.command --keep-originals "/路径/IMG_1234"
/Users/retriedstormtrooper/Downloads/LivePhotoHDR/HDR重建.command --check "/路径/IMG_1234"
```

每个 PVT 旁边生成同名 `.pvt.receipt.json`，其中记录备份路径、运行目录、源文件哈希、源码哈希和验证结果。恢复原件时，将相应备份文件夹从 `.LivePhotoHDR-originals/` 移回原路径即可。Finder 中按 `Command+Shift+.` 可显示隐藏目录。

重建采用本机 AVFoundation、Core Image、Metal、Vision 和 CMImaging。线性缩略图使用包含暗部 toe 的完整分段 Apple Log 反变换，再由本机颜色管理转换到线性 Display P3。逐帧按 `h_video/h_photo` 归一化场景尺度，在真实 PTS 上插值。配对照片的原生 HDR 解码结果提供输出 look，SDR 配准、双向光流置信度和留出区域评分约束动态 RGB 增益。原生 CMIGuidedFilter 将低分辨率参数上采样。

是否执行摄影风格反向由输入资源和明确的 bypass 状态决定。

| 输入情况 | 处理方式 |
| --- | --- |
| 已应用 Smart Style，包含 Delta Map 和反向系数 | 使用原生 useCase 2 反向接口生成 unstyled guide |
| MOV 明确标记 `smartstyle.bypassed=1` | 保留当前像素作为 guide，跳过去风格 |
| 已应用风格但没有 Delta Map | 使用当前画面和场景缩略图约束的 fallback，报告标记 `styled-scene-fallback`，不声称已原生恢复 unstyled |

有无 Delta Map 都可以进入 HDR 重建，但需要真实的照片 HDR 参考、视频线性缩略图、逐帧摄影风格元数据和 still-image-time。当前已实现和验证的元数据版本是 0.16。缺少必要 HDR 参考或对应资源时，脚本拒绝替换原件。

输出为原始编码画布尺寸的 HEVC Main 10、BT.2020、HLG，保留 clean aperture、画面方向、逐帧 PTS 和其他轨道的压缩数据。照片除重新配对的 UUID 外保持相同。CLLI 的未知亮度值写为 0，观看环境采用名义 314 lux、D65，不冒充拍摄环境测量。

HDR 是根据低分辨率场景参考和配对照片估计的结果。脚本不会声称恢复已经丢失的高频高光。PVT 的本机解码、配对与容器检查不等同于 iPhone Photos 中摄影风格编辑、保存和重新打开的验收。

此工具是从独立实验复制出来的本地版本，代码完全放在本目录，不修改主研究线程的源码或工作目录。运行依赖 Apple Silicon Mac、当前系统的私有 CMImaging 功能、Xcode command line tools、`ffprobe`、`exiftool`，以及 Python 的 `numpy` 和 `scipy`。当前机器已具备这些依赖。
