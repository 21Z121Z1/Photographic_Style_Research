# StyleDeltaMap macOS App

Date: 2026-05-31

## Scope

This app is a native macOS operator shell for the existing Photographic Style Research tooling. It does not implement a visual companion pane and does not replace the validated Python/HEIF pipelines. Its job is to collect paths and options, build safe process argument arrays, run the existing tools, and preserve logs/history for direct style injection, auxiliary raster reconstruction, and HEIF validation.

The app intentionally keeps Apple Photos behavior claims separate from tool execution. The direct injection workflow wraps the current `tools/inject_style_family.py` path that can produce Photos-activating HEICs when supplied with a compatible base/donor/template. The gain-map and DNG reconstruction workflows remain experimental diagnostics.

## Architecture

- `Package.swift`
  - `StyleDeltaMapCore`: library target for non-UI behavior.
  - `StyleDeltaMap`: SwiftUI executable target.
  - `StyleDeltaMapTests`: XCTest target for command construction, repository discovery, and process running.
- `Sources/StyleDeltaMapCore`
  - Config models for direct injection, reconstruction, validation, workflow selection, run state, and command results.
  - `RepositoryLocator` resolves the repo from `STYLEDELTAMAP_REPO_ROOT`, the staged app bundle, or the current directory.
  - `ToolEnvironment` resolves Python from `STYLEDELTAMAP_PYTHON`, app settings, or `/usr/bin/env python3`.
  - `ToolCommandBuilder` emits argument arrays for `inject_style_family.py`, `aux_generator.py`, `semantic_fitter.py`, and `heif_dump.py`.
  - `ProcessRunner` uses `Process` with stdout/stderr pipes and runtime buffering, avoiding shell interpolation.
- `Sources/StyleDeltaMap`
  - `WindowGroup` app with regular activation.
  - `NavigationSplitView` workflows: Direct Injection, Gain Map / RAW, Validation, Run History.
  - `Settings` scene for repository, Python, output, donor, and template defaults.
- `script/build_and_run.sh`
  - Builds with `swift build`.
  - Stages `dist/StyleDeltaMap.app`.
  - Writes `Info.plist` and `PkgInfo`.
  - Signs with `STYLEDELTAMAP_CODESIGN_IDENTITY`, the first local `Apple Development:` identity, or ad-hoc signing.
  - Supports `run`, `--debug`, `--logs`, `--telemetry`, and `--verify`.

## Workflows

Direct Injection:

```bash
tools/inject_style_family.py \
  --style-donor <donor.heic> \
  --preview-jpeg <preview.jpg> \
  --make-base-with-sips \
  --base-size <width>x<height> \
  --template <template.heic> \
  --output <output.heic>
```

Gain-map / RAW reconstruction:

```bash
tools/aux_generator.py inspect-gainmap <input> --gainmap-mode auto
tools/aux_generator.py linearthumbnail-gainmap <base> <gainmap> --max-dim 1024 --gainmap-mode auto --output <png>
tools/aux_generator.py linearthumbnail-dng <dng> --preview <jpg> --max-dim 1024 --preview-mix 0.25 --output <png>
tools/aux_generator.py styledeltamap-gainmap <gainmap> --width 720 --height 540 --amplitude 6.0 --gainmap-mode auto --output <png>
```

Validation:

```bash
tools/semantic_fitter.py <candidate.heic> --json <report.json> --md <report.md>
tools/heif_dump.py <candidate.heic> --json <dump.json> --md <dump.md>
```

## Running

From the repository root:

```bash
/bin/bash script/build_and_run.sh
/bin/bash script/build_and_run.sh --verify
/bin/bash script/build_and_run.sh --logs
```

The Codex Run action uses `/bin/bash ./script/build_and_run.sh`. Direct script execution was not used for the Run action because this local machine can leave generated shell scripts with `com.apple.provenance`, which made direct `./script/build_and_run.sh` execution hang in dyld before the script body ran. Running through `/bin/bash` avoids that host-specific launch-path issue.

## Boundaries

- The app does not claim the residual formula matches Apple's real styledeltamap generation.
- The app does not claim new Apple Photos compatibility beyond the existing direct injection tool behavior.
- The app does not embed a visual preview/companion surface.
- The app does not shell-join user paths. Commands are displayed as shell-like text for logs, but execution uses `Process.executableURL` plus `Process.arguments`.
